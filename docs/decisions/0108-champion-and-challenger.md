# 0108. Champion and challenger: decided experiments stay live, and every version is compared on all of them

Date: 2026-11-24. Status: accepted (lane `champ`, branch `feat/champion-challenger`). Builds on ADRs 0104, 0105, 0106 and 0107; replaces the "historical, not rerun" rule of ADR 0106.

## Context

ADR 0106 let an experiment age: once the algorithm moved on, its results were historical, checked for their registration, freeze and inputs, and never rerun. That throws away the most useful thing a decided experiment has, a registered design with registered seeds that can measure any later version. The owner asked that "with the experiments we need to constantly reuse and adapt based on their results, we aim for the best", and, from ADR 0107, that "every experiment we run is actually valuable and not just wasting resources and time".

Two experiments are decided today, both on `algo-1.1.0+fa5e2186e1dd`. EXP-0001's pilot is 3,840 games through the real pipeline: 1,489 seconds with 8 **Stockfish 19** engines, about 2.44 CPU-hours, and it needs **Postgres**. EXP-0002 is 49,600 profile computations and no engine: 1,592 seconds on one core, about 0.44 CPU-hours. Both run in about 25 minutes of wall time on the documented machine.

## Decision

1. **The champion is the production algorithm.** In a pull request it is main's `algorithm/manifest.json`; on the weekly run it is the newest release tag's; on a release it is the release before. Every change is a challenger.
2. **Decided experiments stay live.** A decided experiment's `summary.md` says `live: true`, how often it is re-run (`rerun: per-pr|weekly|release`), and the measured cost of one run (`run_cpu_hours`, `run_minutes`), with its comparison rule in `arena.py` next to `analysis.py`; or `live: false` with the reason in `retired`. `python -m rematch_lab.experiments check` enforces it. A scope runs its own experiments and every cheaper one: `weekly` runs `per-pr` and `weekly`, `release` runs all three.
3. **The arena compares on identical seeds and inputs.** `python -m rematch_lab.arena` runs each live experiment's frozen `analysis.py` for both versions on the registered seed namespace, with `--algorithm <id>` and that version's `cli`, and compares them with the experiment's own rule: per primary and guarded metric, the effect, its interval and a verdict (better, worse, no clear difference). A record is reused only with the same seed namespace, `analysis.py` sha256 and `inputs.sha256`; the committed `results.json` is the record of the version it ran on, so nothing is re-run that a cache answers.
4. **The rules are the experiments' own.** EXP-0001: recall at 2 at 80 games with the paired two-sided 97.5% Newcombe interval (its registered ship rule); coverage up to 80 games as the change in the distance from 0.8 with an 80% paired cluster bootstrap, and clean false alarms with the 80% Newcombe interval (ADR 0104's guard level). EXP-0002: the worst of the 20 coverages (the primary EXP-0006 registered for a comparison on this design) and the coverage at ρ = 1 (its guard), as the change in the distance from 0.8 with the MOVER interval of the two Bonferroni intervals. EXP-0002's results keep coverages, not each player's flags, so that interval ignores the correlation of two versions on the same seeds and errs towards "no clear difference".
5. **The budget is planned before anything runs.** The arena costs the runs the caches cannot answer from `run_cpu_hours` and refuses the plan past its scope's budget (1 CPU-hour per pull request, 4 a week, 8 a release, unless `--max-cpu-hours` says otherwise). A run is stopped at 150% of its measured `run_minutes` (times `ARENA_SLOWDOWN`, 2 on a hosted runner), and each experiment's own `Budget` still caps what it counts (ADR 0107).
6. **EXP-0002 is `per-pr`, EXP-0001 is `release`.** EXP-0002 costs 0.44 CPU-hours on one core with no engine and no database, and it measures the profile layer that EXP-0006 will change first, so a pull request that bumps the algorithm version pays for it. EXP-0001 costs 2.44 CPU-hours with 8 engines and **Postgres**; its primary, recall at 2, is already gated on every pipeline pull request by the smoke suite and measured weekly by the full suite (`bench.yml`), so a weekly EXP-0001 would buy little, and it runs on release.
7. **The shipping gate.** `lab.yml` runs the arena when a pull request changes `algorithm/manifest.json` (`per-pr` against main), every Monday (`weekly` against the newest release) and from `release.yml` (`release` against the release before; the images wait for it). A clear regression on a primary or a guarded metric fails the job. A behaviour change ships when the experiment registered for it says ship and the arena shows no clear regression elsewhere; a challenger replaces the champion on the leaderboard only when it beats it on the primaries.
8. **The leaderboard is committed, in `lab/leaderboard.json`.** Each record holds the version, the experiment, the seed namespace, the sha256 of the analysis, inputs and results, the compact measures the comparison needs, the metrics with their intervals, the champion it was compared with, the verdict and the date. A pull request that bumps the version must commit its challenger's record (`--require-records`), and CI re-runs the challenger and fails when the run differs from the committed record (`--verify`). The weekly and release runs write the file to their artifact and never push. The site's Experiments page renders it: a row per version, a column per live experiment's primary metric, the champion marked.
9. **The emergency override is an ADR.** In an emergency (a security fix that cannot wait for a fix of its regression) the owner writes an ADR that names the version, the experiment, the metrics and the reason, and adds the same to `lab/overrides.json` (`algorithm_id`, `experiment`, `metrics`, `adr`, `reason`). The arena then reports the regression as "overridden" and passes. An entry whose ADR file does not exist does nothing. A release whose images the arena held back is published by hand after the override is merged (re-publishing the Release starts `release-images.yml`).
10. **Every decision ends with a Next.** A decided experiment's `decision.md` has a `## Next` section whose numbered items each name a roadmap issue, by an `EXP-NNNN` id with its experiment issue in `.github/settings/roadmap-issues.json` or by `Issue: "<exact title>"`, and at least one item is an experiment issue. `scripts/github/test-settings.mjs` enforces it on every pull request.

## Options considered

1. **The leaderboard on the `bench-history` data branch.** Rejected for now: the records are deterministic (the same version and seeds give the same bytes), so a person can commit them and a reviewer can read them in the pull request, with no bot writing anywhere; the site builds from the commit with no fetch; and the branch does not exist yet. `bench-history` stays the home of the RunRecords, whose timings depend on the machine (ADR 0104).
2. **Re-run every live experiment on every pull request.** Rejected: 2.88 CPU-hours a pull request, most of it EXP-0001's engines, for a primary the smoke suite already gates.
3. **Keep the historical rule.** Rejected: it discards registered designs that can measure every later version, against the owner's "we aim for the best".
4. **A single generic comparison for every experiment.** Rejected: each experiment registered its own unit, interval and level; a generic rule would compare EXP-0001's players as if they were independent games.

## Consequences

- A pull request that bumps the algorithm version costs about one extra EXP-0002 run in CI, and its author commits the arena's `lab/leaderboard.json` (the job's artifact holds it).
- The release pipeline waits for the arena, about an hour on a hosted runner for EXP-0001, longer when the release before has no cached record and its `cli` is built.
- When an experiment's design changes, its old records stop being reused (the sha256 differ), and the next run writes new ones.
- `docs/evaluation.md` ("The loop: champion and challenger"), `lab/README.md` and `lab/experiments/README.md` describe the loop; ADR 0106's historical rule is replaced.
