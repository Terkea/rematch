# R1: Rust Backend Core (port of Milestone 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the TypeScript Milestone 1 backend (`packages/chess-core`, `packages/db` as schema owner, `apps/worker`, BullMQ, Redis) with a Rust cargo workspace that is behaviourally identical (same `moves` rows, same accuracies, same recovery guarantees), measurably cheaper per game, and then delete the TypeScript backend.

**Architecture:** The cargo workspace `backend/` holds library crates `chess-core`, `db`, `queue`, `engine`, `platforms`, `analysis` and `events`, a dev-only `testkit`, and the binaries `worker` and `cli` (plus a `parity` dev tool). Postgres is the only stateful service: plain SQL migrations in `db/migrations/` (applied by sqlx) are the schema source of truth, a `jobs` table with `FOR UPDATE SKIP LOCKED`, leases and LISTEN/NOTIFY replaces BullMQ and Redis, and `user_events` plus `NOTIFY` replaces Redis pub/sub. The TS code on branch `build/m1-foundation` (HEAD c66428e) is the reference specification: every TS test is ported, and a parity harness compares the two workers' output on the same games before the TS backend is removed.

**Tech Stack:** Rust 1.100.0 (stable, 2026-11-09), tokio 1.54.1, sqlx 0.9.1 (Postgres 17), reqwest 0.13.5 (rustls), cozy-chess 0.3.4, serde 1.0.229 / serde_json 1.0.154, thiserror 2.0.21, tracing 0.1.44 / tracing-subscriber 0.3.23, clap 4.6.9, Stockfish 19, Docker Compose, cargo-chef 0.1.78, cargo-deny 0.22.0.

**Spec:** `docs/superpowers/specs/2026-11-21-chess-improver-design.md` (§6 note, §7, §8, §8c, §8d, §13, §13a), `docs/research/improvement-engine.md` §4.1, ADR 0030 (`docs/decisions/0030-rust-backend.md`), ADRs 0023 and 0026–0029. **Reference implementation:** the main checkout `E:\code\chess-improver` on branch `build/m1-foundation` (`packages/chess-core/**`, `packages/db/**`, `apps/worker/**` including `src/cli.ts` and `test/cli.test.ts`). Base all R1 work on that branch.


> **Controller amendment (R1 T1 fix, ADR 0031):** `chrono` is NOT used. Every timestamp is `time::OffsetDateTime` (`DateTime<Utc>` in this text means `OffsetDateTime`; `Utc::now()` means `OffsetDateTime::now_utc()`). JSON timestamps that must match the TS reference / `Date.toISOString()` use `#[serde(with = "chess_core::js_time::iso")]` (or `::option`), which always writes UTC with exactly 3 fractional digits. sqlx uses its `time` feature.

## Global Constraints

- **Build and test only in containers.** The host is Windows with no Rust toolchain. Every cargo command runs as `docker compose run --rm rust-dev <cmd>` (working directory `/work/backend`). In this plan, `$RUST` means exactly `docker compose run --rm rust-dev`.
- **Parallel lanes share one Compose project.** Each lane exports `LANE=<lane letter>` before running `$RUST`, so its cargo target dir is `/target/$LANE` inside the shared `rust_target` volume. Postgres is shared, and `#[sqlx::test]` creates a uniquely named database per test, so lanes never collide.
- **Ports bind to 127.0.0.1** (Postgres `127.0.0.1:55432`). Never touch containers of other projects (the host runs `velvet_lab_db` on 5432). Redis stays only until Task 27 removes it.
- **Toolchain:** `backend/rust-toolchain.toml` pins `channel = "1.100.0"` with components `rustfmt`, `clippy`. Docker base images are `rust:1.100.0-slim-bookworm` (build) and `debian:bookworm-slim` (runtime).
- **Lockfile ownership:** Task 1 declares every dependency of every crate (in `[workspace.dependencies]` and each crate's `Cargo.toml`) and commits `Cargo.lock`. No later task edits any `Cargo.toml` dependency list or `Cargo.lock`. A task that needs a new crate stops and reports it. The coordinator then adds it in one commit on the base branch, and lanes rebase.
- **Shared files are pre-created by Task 1:** every crate's `lib.rs` module list (with empty module files), `testkit` module files, and the R1 ADR index rows in `docs/decisions/README.md`. Migration versions are reserved in Task 1, and each migration file is created by its owning task. A lane edits only the files its task lists.
- **Licences:** only MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Unicode-3.0, Zlib (and `OR`/`AND` combinations of them). No shakmaty or pgn-reader (GPL-3.0), and no copyleft crates. If `cargo deny check` finds any other licence, stop and resolve it with an ADR addendum. Never widen the allowlist silently.
- **Analysis protocol:** `ANALYSIS_PROTOCOL = "sf19-n300k-v1"`, `ENGINE_NODES = 300_000`, MultiPV 1. The engine pool sets neither `Threads` nor `Hash` (the Stockfish defaults, exactly like the TS pool), so searches are deterministic and comparable with TS output.
- **Formulas exactly as improvement-engine §4.1** and the TS reference: `WIN_K = 0.00368208`, cp clamped to ±1000, mate = ±1000. Move accuracy is `103.1668100711649 * exp(-0.04354415386753951 * d) - 3.166924740191411 + 1`, clamped to [0, 100]. Judgement thresholds are 0.3, 0.2 and 0.1 in winning chances, plus the mate rules with −999/−700 and 999/700. All arithmetic is `f64`.
- **Time class:** est = base + 40·increment; bullet < 180, blitz < 480, rapid < 1500, else classical; chess.com `1/N` = daily.
- **Outbound HTTP:** one request at a time per platform client. `User-Agent: chess-improver/0.1 (+mailto:${CONTACT_EMAIL})`, where `CONTACT_EMAIL` is required and has no default. 429 means wait 60 s and retry up to 3 times. The request timeout is 30 s, and the stream idle timeout is 60 s between chunks.
- **Every DB and network call has a timeout:** Postgres `statement_timeout = 30s` on every worker connection, a pool `acquire_timeout` of 10 s, the HTTP timeouts above, and the engine timeouts (30 s per position, 10 s handshake).
- **Tests:** a DB test is `#[sqlx::test(migrator = "db::MIGRATOR")]` (a fresh database per test). There is no truncation and no `_test` name guard, because sqlx creates and drops its own databases. When `IN_DOCKER=1`, a test that needs Stockfish or Postgres **fails** (panics) instead of skipping. Only recorded fixtures are used, with no live network, except Task 25.
- **Port naming rule:** a ported TS test keeps its title, converted to snake_case (`"pool recovers after engine crash"` → `pool_recovers_after_engine_crash`), and asserts the same values as the TS test. The parity checklist at the end maps every TS test file to its Rust test file.
- **Timing in tests:** wall-clock assertions use generous bounds (at least 3× the expected value), or poll with `testkit::wait_for`. Never assert a tight sleep.
- **SQL style:** runtime-checked `sqlx::query`/`query_as` with `#[derive(sqlx::FromRow)]`. No `query!` compile-time macros, so building needs no `DATABASE_URL` and there is no `.sqlx` cache for parallel lanes to fight over (ADR 0031). Postgres enums are bound as text with explicit casts (`$1::analysis_status`) and read back as `col::text`. `chess-core` stays free of sqlx.
- **ADRs:** every decision gets an ADR. R1 uses the pre-assigned numbers 0031–0038 (see Task 1), each written by the task that owns it.
- **Commits:** Conventional Commits, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **chess.js byte-compatibility of FEN, UCI and SAN.** The FEN includes the en-passant square only when a *legal* en-passant capture exists. Castling UCI is `e1g1`/`e1c1`, not cozy-chess's king-takes-rook `e1h1`. The SAN uses chess.js disambiguation and `+`/`#`. `fen_before` and `fen_key` are the eval-cache key, so any drift splits the shared cache and breaks parity. Test: Task 3 `fen_matches_chess_js_for_reference_positions`, `castling_uci_uses_king_destination`, `ep_square_only_when_legal_capture`.
2. **`toFixed` rounding in the CLI summary line.** Rust's `{:.2}` rounds ties to even (9 blunders over 8 games prints `1.12`), but JS `toFixed` prints `1.13`. Test: Task 23 `to_fixed_matches_js_on_ties`.
3. **Shutdown on a job's final attempt must not dead-letter the game.** A closed engine pool releases the job without using an attempt, and the game stays `pending`. Test: Task 19 `pool_closed_on_final_attempt_releases_without_attempt`, Task 22 `sigterm_on_final_attempt_then_fresh_worker_completes`.
4. **A stale worker must not complete a job it no longer leases.** After its lease expires and the job is re-claimed, the old worker's complete, fail and renew calls are no-ops (lease-token fencing). Test: Task 14 `expired_lease_holder_cannot_complete`.
5. **A client whose Last-Event-ID predates the 7-day pruning** gets a `reset` marker, so it refetches its state instead of silently missing events. Test: Task 16 `list_events_after_signals_reset_after_prune`.

## Intentional deviations from the TS reference (all recorded in ADRs)

1. One live import job per account (dedupe key `import:<account_id>`). This replaces BullMQ's `resume-import-<runId>` ids (ADR 0032).
2. A `not_found` import is unrecoverable: no retries, and `job.failed` is published (ADR 0035).
3. Shutdown and a closed engine pool release the job without using an attempt. TS dead-lettered it on the final attempt (ADR 0035).
4. A breaker re-delay reuses the account's `paused` run row. TS created a new run per delay (ADR 0035).
5. Analysis generations: attempts reset on a re-analysis request, and "done at the current protocol" is generation-aware (ADR 0035).
6. `list_events_after` returns a `reset` flag. Live delivery uses `NOTIFY user_events` from inside the insert transaction (ADR 0034).
7. "Queues idle" in the CLI is scoped to the account's own jobs (`user_key`). TS checked whole queues.
8. The PGN clock extractor strips *nested* variations correctly. TS stripped only one nesting level, which affects no recorded fixture (ADR 0037).
